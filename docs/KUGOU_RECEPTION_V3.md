# 酷狗店铺 Reception V3：分阶段接待与知识治理

> 状态：功能护栏第一阶段已实装，流程配置和自动履约授权仍需后续上线验证。本文是当前店铺的专属业务规则草案，不应复制到其他店铺。

## 一、来源与限制

- 来源：2026-10-29 店主完整业务原文、导出的 Knowledge V2 共 844 条以及 10 月 27—29 日现场请求日志。
- 真实出售权益定义：店主称全店两个商品链接最终销售同一种酷狗超级会员，具体 SKU 价格、期限与订单情况必须取实际商品及订单快照。
- 商品：1057505313937（电视关键词入口）和 1066362196568（另一个酷狗会员入口）；不得通过标题推断最终使用设备。
- 不得故意错误回答“手机端不通用”。买家询问手机、车机或跨端时必须如实回答实际权益，并说明兼容性条件。
- 店主业务说明只作为店铺内部政策与审核依据；设备厂商规则、第三方会员权益、退款法律问题在发布前应核实。

## 二、状态机和授权动作

| State | 进入证据 | 允许动作 | 禁止动作 |
|---|---|---|---|
| awaiting_order | 未核实订单 | 提供真实商品和 SKU 信息 | 伪称已付款 |
| awaiting_account_screenshot | 已付款且当前设备需要截图 | WAIT / ASK_EVIDENCE | 手机号代替截图、重复问无关问题 |
| need_resource_confirmation | 图片不能确定音乐资源来源 | ASK_EVIDENCE / HANDOFF | 按电视品牌直接判支持 |
| awaiting_binding_proof | 已判定酷狗资源但未证实买家本人账号绑定 | SEND_VERIFIED_GUIDE / WAIT | 开通、声称已绑定 |
| awaiting_order_review | 已看到绑定证据但仍需核对订单 | HANDOFF / WAIT | 自动声称充值成功 |
| device_rejected | 证实当前栏目不属于店铺受理范围 | 拒绝该栏目充值并指导平台退款/人工核实 | 混同同品牌的独立官方 APP |
| human_handoff | 人工已介入 | WAIT、保留证据与阶段 | AI 旧答复抢答 |
| completed | 真实履约完成且有确认回执 | 售后帮助 | 继续索取不必要账号信息 |

订单已付、设备兼容、当前账号已绑定、实际充值动作、到账状态是五个独立事实。

## 三、设备规则（先核验类型，再核验版权与账号）

- 手机、电脑、平板：对于经确认的官方酷狗应用，不应要求电视截图。
- 电视独立安装的官方酷狗应用：独立判断能否登录本人酷狗账号；听歌和 K 歌分别看实际应用功能。
- TCL/雷鸟内置音乐：必须区分酷狗与 QQ 资源；店主要求本人可反复登录的 TCL 电视账号，如已绑定旧账号先解绑，使用通用扫码、登录本人酷狗账号，最终获得明确的已绑定页面。教程：https://howhub.k2n.cn/guide/tcl-ln。
- 海信/聚好看/VIDAA 等系统内置栏目：按店铺政策不受理充值（此判断针对系统自带栏目而非整台电视或独立安装的官方酷狗应用），若已下单则按真实订单流程进行人工退款。
- 小米系统自带 K 歌：店主不受理；小米内置听歌需要看酷狗/QQ 资源归属。独立官方 App 不由品牌直接否定。
- 海尔/酷喵：具体截图/账号教程尚未提供，缺少证据不得生成确证结论。
- IPTV、华数、点歌机、运营商话费支付会员系统按店铺政策不在受理范围；不能仅凭品牌名称排除独立官方酷狗 App。

## 四、工程实现清单

- P0：KugouReceptionPolicy 只作用于已拥有目标商品 ID 的店铺。V2+旧 SmartReply 均隔离 8 条已确证错误/高风险知识，保留 DB 原记录；发送前对错误权益/退款断言设门禁。
- P0：premerge 的手机号等待决策优先于普通短答、AI 和人工代充；订单自动回复保留自己的业务授权链路。
- P1：视觉回复使用本轮图片的 OCR 和 visual_summary 做策略判断；不从商品标题推断；TCL 教程真实 URL 内置在经审核规则里。明确指向图片的短追问窗口 90 秒，非指代消息维持 45 秒。
- P1：每店铺最近 300 条、最近七天的脱敏审计存入 shop rules directory 的 kugou-reception-decisions.json；短时阶段仅用于提示，不可作为订单充值完成证据。
- P2：最后消息五分钟后复盘，产出流程阶段/触发/证据/动作/下一阶段候选，标记 manual_review，不自动启用；涉及兼容/充值等知识候选不自动推广。审核和正式发布仍应通过人工确认和版本控制。

## 五、上架前验证

1. 在非生产店铺/测试窗口验证 P0 不误伤其他店铺或非酷狗商品。
2. A：订单已付→照片要求→买家仅发手机号→不回复，审计 WAIT。
3. B：TCL 内置音乐绑定页显示 QQ 音乐账号→不发送酷狗充值承诺，安全解释。
4. C：TCL 内置资源未识别/未绑定→先发真实教程并等待绑定照片。
5. D：TCL 显示已绑定酷狗账号→只进入待核实订单，不直接标充值成功。
6. E：海信系统内置音乐拒绝受理；海信自行安装的官方酷狗应用仍允许单独核验。
7. F：人工回复后晚到的文本和视觉 AI 答案被抑制，订单系统固定通知不被该普通 AI 门禁误挡。
8. G：低置信 OCR/图片/模糊文字不产生强制支持结论。
9. H：五分钟学习的流程提案可在报告查看，但生产知识库未自动更改。
10. 在任意错误上线时支持回退 PR 或禁用专属模块，保持原始知识导出和店铺规则备份。
