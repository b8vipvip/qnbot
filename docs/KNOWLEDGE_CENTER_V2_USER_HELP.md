# Knowledge Center V2 客户端使用帮助

最后更新：2026-08-25

客户端可从以下位置打开同一份只读帮助：

- `设置 → 知识库 → 使用帮助`
- 设置窗口右上角帮助入口（当前页面为“知识库”时）
- `Knowledge Center V2 → 使用帮助`

帮助窗口不会保存设置、修改知识或触发同步。

## 推荐首次配置

1. 在 `设置 → 店铺与连接 → 店铺绑定` 核对当前店铺。知识、V2 设置、反馈、修订和治理历史都按 `ShopKey` 隔离。
2. 进入 `知识中心 → 导入导出`，先导出 V2 完整包。
3. 在 `设置 → 回复与通知 → 自动回复规则 → 回复模式` 选择回复模式：
   - `AI优先`：本地知识作为上下文，由 AI 生成最终答案。
   - `本地优先`：高置信知识可以零 AI 直答；不满足条件时继续回退兼容 AI 链路。
4. 在 `知识 / 商品知识 / 流程` 页录入结构化知识。
5. 进入 `知识中心 → 设置`：
   - 启用 `Knowledge Engine V2`；
   - 首次上线先用 `shadow`；
   - 默认直答匹配阈值 `0.82`；
   - 默认最低知识可信度 `0.68`；
   - 保存后点击 `立即预热索引`。
6. 在 `测试台` 用典型问法、同义问法、上下文短句和易混淆问法验证 Top Matches 与拒绝原因。
7. 处理 `冲突` 和 `学习` 页待办后，再切换 `production`。

只有以下条件同时成立时才可能本地直答：

- 回复模式是 `本地优先`；
- V2 已启用且模式是 `production`；
- 知识是 `Enabled=true / Status=active`，不是学习候选；
- 同一事实键没有有效答案冲突；
- 问题与答案不属于高风险；
- 匹配分、综合可信度、Alias/Predicate 明确度和候选分差全部达标。

## 结构化字段

当前 V2 索引主要依据标题、Aliases、Intent、Predicate 和 Entities 召回与排序。

| 字段 | 填写方法 |
|---|---|
| 标题 | 写成买家会问的完整标准问题，不要只写宽泛名词 |
| Intent | 买家目的；常用 `general / capability / purchase / price / time / how_to / troubleshoot / requirements / after_sale` |
| Subject | 业务对象；同一对象保持同一写法，例如 `示例音频应用/电视/会员` |
| Predicate | 询问属性；常用 `membership_type / purchase_channel / price / device_support / feature_support / activation_method / account_binding / refund_policy / time / troubleshooting / requirements` |
| Entities | 品牌、平台、设备、会员、功能等实体；建议每行一个 |
| Aliases | 同义问法和常见口语；高度匹配 Alias 是本地直答的重要条件 |
| 标准答案 | 当前本地直答实际使用的答案；只能写已经确认的业务事实 |
| 简短答案 | 可选结构化摘要；当前本地直答仍以标准答案为准 |
| 适用/排除条件 | 记录渠道、版本、商品等适用边界 |
| 必要上下文 | 记录回答前必须确认的信息；不能绕过上层安全门控 |
| 商品 ID | 用于商品知识分类、统计和完整包迁移；每行一个精确 ID |
| 风险等级 | `normal / high`；高风险知识不会本地直答 |
| 可信度/权威度 | `0~1`；不要为追求直答率全部填写 `1` |
| Enabled/Status | 正式知识通常为 `true / active`；`candidate` 不直答，`disabled` 不进入运行时索引 |

列表字段支持逗号、中文逗号、分号、竖线或换行分隔，推荐每行一个值。

### 知识类型

- `business_fact`：普通业务事实。
- `procedure`：操作、绑定、充值或激活步骤。
- `presale`：售前能力、购买或价格事实。
- `product_knowledge`：明确商品知识。
- `order_rule`：订单规则。
- `after_sale`：售后规则。
- `safety_rule`：退款、账号、安全、法律等边界事实。
- `fixed_reply`：固定话术。
- `temporary`：需要定期复核的临时知识。
- `learning_candidate`：自动学习或人工纠正候选，需人工批准。

### FactKey 与冲突

事实键为：

```text
Compact(Subject) + "|" + Predicate
```

只有相同 `Subject + Predicate` 的不同答案才是冲突。例如“电视会员是什么”和“电视会员在哪里买”可以拥有同一 Subject，但 Predicate 分别为 `membership_type` 和 `purchase_channel`，因此不是冲突。

## 回复工作原理

1. 当前买家消息先解析 `Intent / Subject / Predicate / Entities`。
2. 只有“这个呢”“能用吗”等缺少主体的短句，才使用最近 45 分钟的买家级 Working Memory 补全。
3. 每个店铺独立 Snapshot 使用 Exact、Intent、Predicate、Entity 和中文 2-gram 索引召回有限候选。
4. 排序综合 Predicate、Entity、Intent、Alias、知识可信度和真实反馈小幅修正。
5. 通过全部直答门控时，标准答案进入既有安全发送链路。
6. Shadow、冷索引、无候选、分数不足、冲突或高风险时，不勉强发送，继续走 Smart Reply / AI 兼容链路。

本地知识答案仍要经过自动回复开关、任务有效性、并发相关性、目标买家确认、去重、Bot 消息后缀、`SendTextWithRetryAsync`、发送回显和失败诊断。

普通新增和编辑使用当前店铺 Snapshot 的原子增量更新；批量替换和重新迁移使用完整 Snapshot 替换。买家消息不会承担定时全量索引重建。

## 学习、质量、修订与治理

### 学习

接待结束复盘、人工最终回复等学习来源先生成：

```text
Type = learning_candidate
Status = candidate
```

候选不会参与本地直答。必须在 `学习` 页点击 `批准入库` 才能成为正式知识。

### 质量

- 真实发送成功才记录 `sent`。
- 明确认可记录 `accepted`。
- 明确否定后人工给出不同答案记录 `correction`。
- 撤回记录 `withdrawal`。
- 发送失败记录 `send_failed`，但不作为知识错误证据。

质量页当前只提示和轻度修正排序，不自动禁用知识。

### 修订

修订候选来自最近 120 天的真实人工纠正聚类，不由 AI 编造事实。普通候选至少需要 2 次纠正和 2 个不同买家；高风险知识至少需要 3 次纠正和 3 个不同买家。应用和驳回必须人工触发；原答案后来被人工编辑时，候选会变为 `stale` 并拒绝覆盖。

### 治理

治理扫描集中显示低质量、冲突、待复核修订、验证过期、长期未使用和建议回滚。扫描只读，停用、应用和回滚都需人工确认。

治理设置按店铺独立：

| 设置 | 默认值 | 范围 |
|---|---:|---:|
| 普通知识验证过期 | 180 天 | 30–730 天 |
| 高风险知识验证过期 | 60 天 | 7–365 天，且不得大于普通阈值 |
| 长期未使用提醒 | 120 天 | 30–730 天 |

设置只决定何时进入治理队列，不自动修改知识。治理历史采用追加式审计，答案只记录 SHA-256 指纹。

回滚建议仍至少要求：修订后 3 次有效发送、2 次负向证据、25% 负向率，并且比修订前恶化 15 个百分点。满足门槛也不会自动回滚。

## 备份和数据保护

当前店铺知识目录包含四个独立数据库：

```text
knowledge-center-v2.db
knowledge-feedback-v2.db
knowledge-revision-v2.db
knowledge-governance-v2.db
```

- `导出V2完整包` 包含全部结构化知识、V2 设置和 Schema Version。
- `导入V2完整包` 会替换当前店铺 V2 知识和包内设置，但导入前自动创建 JSON 备份并要求确认。
- `仅导出结构化知识` 不包含完整 V2 设置。
- `从旧知识重新迁移` 会重建当前店铺 V2 数据，只应在已经导出完整包并明确需要时使用。
- 程序升级不得覆盖 `data`、`params.db`、店铺配置、账号信息或知识数据库。

### 旧版知识库预览

在 `设置 → 知识库` 点击 `旧版知识库预览`，可以只读查看当前 ShopKey 已保存的旧版问答快照，包括启用标记、分类、问题、答案、关键词、来源、创建/更新时间和 ID。该窗口只提供搜索、分类筛选、详情查看和刷新，不挂载旧版管理界面，不提供新增、编辑、删除、导入导出或 AI 优化，也不会启用旧版检索、匹配或自动回复。多店铺环境不会猜测旧全局数据归属；列表为空且仍有旧数据时，请先在 `店铺绑定` 确认归属。

## 常见排查

### 没有本地直答

依次检查：当前店铺、自动回复开关、`本地优先`、V2 启用、`production`、`Enabled=true / active`、非候选、非高风险、无冲突。然后在测试台查看具体拒绝原因，优先修正 Alias、Entities、Intent、Subject 和 Predicate，不要第一步就降低全店阈值。

### 编辑或导入后没有更新

点击顶部 `刷新`，再到 `设置` 点击 `立即预热索引`；确认编辑的是正确 ShopKey；学习候选需人工批准；云同步问题回到 `设置 → 店铺与连接 → 店铺绑定` 检查 Token、ShopKey 和本店云同步开关。

### 阈值怎么调整

误答时优先拆分混合事实、解决冲突、补适用边界或提高阈值；漏答时先补 Alias / Entities 并查看测试台原因。每次只改一个变量，用同一组测试问题复测，稳定后再进入 Production。
